# ButovskyHOST — Telegram-бот для продажи хостинга

Бот на Python и aiogram 3. Он хранит профили пользователей и заказы в отдельных JSON-файлах, проводит пользователя через выбор тарифа и согласие на использование 20% мощности, а администратору передаёт заказ, чек и инструменты ручной выдачи сервера.

## Возможности

- Создание профиля при `/start`: имя, фамилия, username, статус `A`/`U`/`B`, баланс `0`.
- Главное меню: заказ хостинга, профиль, активные заказы, список серверов с перелистыванием.
- Админ-панель: список пользователей и блокировка/разблокировка, создание и включение/скрытие тарифов, просмотр заказов и серверов.
- Согласие на использование ровно 20% мощности обязательно для оформления заказа; отказ не создаёт заказ.
- Ручной процесс заказа: заявка → администратор берёт в работу → запрос оплаты → пользователь присылает фото/файл чека → администратор подтверждает оплату → вводит IP, логин и пароль → данные отправляются пользователю.
- Пароль сервера шифруется Fernet перед записью в JSON. Сообщение администратора с паролем бот старается удалить после обработки; пользователь получает данные в личном чате с ботом.
- Платёжного шлюза нет: бот сообщает настроенные реквизиты/инструкции и передаёт чек администратору для ручной проверки.

## Запуск локально

Требуется Python 3.10+.

Быстрый запуск на Linux/macOS: из корневой папки проекта выполните:

```bash
bash start.sh
```

Скрипт запросит токен бота (ввод скрыт) и Telegram ID администратора, сохранит настройки в закрытый файл `.env`, создаст виртуальное окружение, установит зависимости и запустит бота. При повторном запуске сохранённый ключ шифрования паролей не меняется.

Ручная настройка и запуск:

```bash
python -m venv .venv
# Linux/macOS
source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
cp .env.example .env
```

Откройте `.env` и задайте:

- `BOT_TOKEN` — токен, выданный `@BotFather`;
- `ADMIN_IDS` — числовой Telegram ID одного или нескольких администраторов через запятую;
- `FERNET_KEY` — ключ шифрования паролей. Сгенерировать:

```bash
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

- `PAYMENT_INSTRUCTIONS` — текст, который увидит пользователь после запроса оплаты.

Запуск:

```bash
python main.py
```

Напишите боту `/start` с аккаунта, указанного в `ADMIN_IDS`, затем откройте панель администратора и создайте первый тариф.

Проверка логики файлового хранилища без запуска Telegram-бота:

```bash
python -m unittest discover -s tests -v
```

## Запуск через Docker

Создайте `.env`, заполните настройки, затем:

```bash
docker build -t butovskyhost .
docker run -d --name butovskyhost --restart unless-stopped \
  --env-file .env \
  -v "$(pwd)/data:/app/data" \
  butovskyhost
```

Каталог `data` содержит персональные данные, заказы и зашифрованные пароли. Ограничьте доступ к нему и делайте защищённые резервные копии. Резервная копия `.env`/`FERNET_KEY` должна храниться отдельно и безопасно: без исходного ключа сохранённые пароли не расшифровать. Не запускайте несколько копий бота одновременно: хранилище рассчитано на один процесс.

## Структура данных

```text
data/
  users/<TelegramID>.json
  orders/<номер-заказа>.json
  tariffs.json
```

Статус пользователя: `A` — администратор (ID из `ADMIN_IDS`), `U` — пользователь, `B` — заблокирован. Баланс создаётся со значением `0`; пополнение баланса и автоматическое списание не входят в ручной процесс оплаты.

## Безопасность и эксплуатация

- Не добавляйте `.env` и `data/` в Git и не отправляйте токен или ключ шифрования в чат.
- Данные хранятся локально в JSON и не синхронизируются с платёжным провайдером.
- Администратор видит чек и введённые им серверные параметры. Telegram-сообщение с паролем старается удалиться ботом; доставку пароля пользователю выполняет Telegram в личном чате.
- Это бот управления заказами, а не автоматический установщик/провижионер серверов. Настройка сервера выполняется администратором вручную.
